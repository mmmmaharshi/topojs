ORDER-SENSITIVITY SWEEP
Generated by: npm run bench -- --order-sensitivity <dataset>  (n=12 seeded random
push-orderings per dataset, Fisher-Yates shuffle via mulberry32, seeds 900001..900012)

PURPOSE. The main benchmark's "repeats"-mode datasets (Iris, Wine, Seeds, Sonar,
Jazz) push their fixed point set in exactly ONE real ordering -- the order the
source file happens to store them in. Iris in particular is class-block-sorted
(50 Setosa, 50 Versicolor, 50 Virginica, in that order), not shuffled. The main
run's "repeats" trials re-time that SAME ordering N times, which checks
measurement/JIT repeatability, not whether the reported speedup is an artifact
of that one convenient ordering. This sweep re-runs each dataset under 12
independent random orderings of the same real points to test that directly.

INTERPRETATION, stated plainly. None of the five "repeats"-mode datasets
reproduce their default-order speedup under random push ordering. Four of
five (iris, sonar, jazz -- CI includes 1x; wine -- CI excludes 1x but on the
LOSING side) show no reliable advantage once the dataset's default ordering
is removed. Seeds is the only one with a positive, statistically-detectable
effect under shuffling, and even there it's 1.40x, not the 2.99x reported for
its default order.

The most likely mechanism: these datasets' default (file) orderings are not
i.i.d. samples from the underlying distribution -- Iris in particular is
class-block-sorted, so consecutive pushes within a class are geometrically
close, keeping deg(new) small and the re-reduced fraction low (favorable for
IncrementalH1's O(deg(new)^2) term). Randomizing the order removes that
structure and lets deg(new) vary the way it would in a genuine online/
streaming deployment, where points do not arrive pre-sorted by class.

WHAT THIS DOES NOT AFFECT. The two "chunks"-mode datasets (sunspots,
Melbourne temperatures) are genuine real time series where push order IS the
signal being measured (delay-embedded from temporal sequence) -- shuffling
them would destroy the thing under test, not remove a confound, so they are
correctly excluded from this sweep and their reported speedups stand as
measured.

HONEST TAKEAWAY. The streaming speedup claim, as previously written in
README.md, generalizes cleanly to genuinely time-ordered real data (2/7
datasets) but was measuring an ordering-dependent effect, not a
push-order-independent property of the algorithm, for the other 5. README.md
has been updated to state this explicitly rather than leave it as an implicit
assumption; any paper draft must report both numbers (default-order and
order-randomized) side by side, and should scope the "1.7x-3.4x across seven
real datasets" headline claim down to what survives: the two time-series
datasets, plus a smaller, qualified effect on Seeds.
