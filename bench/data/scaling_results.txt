series can support with a defensible number of disjoint chunks. windowSize

CONCLUSION (answers the open question):
Raw speedup is NOT monotonic in window size on either dataset -- it peaks
around windowSize=20-40 (1.97x-1.99x) and then DECLINES as window size grows
further (down to 1.30x-1.36x by windowSize=120-160). The "speedup widens
with window size" statement in the original scaling sweep was true only
within the windowSize<=80 range it was measured over; extending the range
reverses the conclusion on both real datasets tested, and on sunspots the
incremental engine's own growth exponent overtakes the naive engine's
(p=2.04 vs 1.89).

This is NOT a bug and does not contradict IncrementalH1's correctness (still
168/168 exact-match tests passing) -- it's an answer to the exact question
bench/data/scaling_results.txt used to leave open: IncrementalH1's speedup is
better explained as a mid-range, density-dependent effect than as an
asymptotically-superior complexity class. A plausible mechanism, consistent
with the complexity already documented in README ("Θ(E+T) + O(k) +
O(deg(new)^2)"): delay-embedded real time series cluster in bounded space, so
as windowSize grows, deg(new) -- the number of existing window points within
maxDist of the newest point -- grows too, and the O(deg(new)^2) term
eventually dominates the O(k) term IncrementalH1 was designed to avoid. This
also matches the already-documented ~150x memory cost getting WORSE, not
better, at larger window sizes (see "Comparison Against Prior Work" in
README) -- both the time and space trade-offs point the same direction:
IncrementalH1 is a real, validated win in a mid-size window regime, not a
strictly-dominant replacement for StreamingHomology at all scales.

PRACTICAL IMPLICATION: at the window sizes this repo's own benchmarks and
demo actually use (windowSize <= 80), IncrementalH1's speedup claim stands
exactly as measured. Users running much larger sliding windows (>100-150
points) should re-benchmark on their own data before assuming the same
advantage holds -- it may have already peaked and started reversing.
