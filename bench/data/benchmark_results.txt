NOTE ON RUN-TO-RUN VARIANCE OF THE AUTOCORRELATION DIAGNOSTIC (added after
statistical review -- see bench/data/summary.txt "Statistical caveat" section
and bench/benchmark.ts pairedStats()): the chunk-order lag-1 autocorrelation
value itself is estimated from only 6-8 points and is NOT stable run to run.
Separate runs measured shortly before this one found sunspots autocorrelation
values of 0.301, 0.397, and 0.419 (n_eff ranging 2.46-3.22) and melbourne-temp
values of -0.272 and 0.422 (n_eff ranging 3.26-8.00) across different runs of
the identical code and data -- pure timing-noise variation, not a data change.
On at least one observed run, the melbourne-temp axis's effective-N-adjusted
95% CI dropped to 0.902x-3.031x, crossing 1x (not significant once the
correction is applied); the run captured above did not show that. Re-run this
benchmark yourself before trusting either the raw or the effective-N numbers
for a specific dataset -- the honest reading is "n=6-8 chunks is too few to
reliably tell whether chunking-induced non-independence is a real problem for
this specific axis," not "the correction proves it is fine." See
bench/data/summary.txt for the full discussion and the recommended fix (more,
shorter chunks; block bootstrap).
